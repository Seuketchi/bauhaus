# peterhans

## What it does

`peterhans` is the photographer. It reads the brief, the project's `DESIGN.md` and the project's own rules, then develops or prepares a photograph the owner supplies and hands back a JPG, a PNG preview, the command that made them and the figures the app printed. The job is the still image after capture.

It calls three tools, each on a stated fact: `design` when no brief file exists, `develop` when the task is a photograph to develop or prepare, and `critique` when a finished image exists that this session did not make. The default is not to call.

The source photograph is never changed. Its hash is taken before and after the run, the output goes to a different path, and every value the app is given is checked against the app's own catalogue first, because the app clamps an out-of-range value and says nothing.

A short `Stance` section sets out how the craft works: hold the variables still, compare two versions side by side, judge against a range and refuse a verdict that stops at liking. It is a method sheet and not a voice.

The split is fixed. The writer owns the words of the pieces made here, donna keeps long documents and the PDF build, `bayer` takes brand, logos and email, `breuer` takes app and web screens, `mies` takes form, plans and structure, and louis reviews.

## When to reach for it

- A photograph needs its exposure, colour temperature or frame set to stated values.
- A photograph needs a JPG for use and a PNG preview for a craft pass.
- A finished image from another session needs a craft pass.

Skip it for brand, logos, email, screens, plans and document text, and for anything that needs a photograph made rather than developed.

## Common questions

**Does it change the original?** No. The original is only read, and the hand-over carries its hash before and after.

**Does it advise on the camera?** It can give a capture note on aperture, shutter and ISO. It cannot act on them, because the app has no such controls.

**Does it write the story or the words?** No. It develops each photograph for a beat of the brief's `Story` and invents none.

**Is this a person speaking?** No. The register is plain and professional, and nothing in the file imitates a real person's voice or attributes words to anyone.

## It's working if

- Every change in a hand-over is a number, and every number equals what the app printed.
- The hash of the source is the same before and after.
- The developed file and the command that made it are handed over together.
- It calls a tool only for the stated trigger, and says in one line which tool and why.
