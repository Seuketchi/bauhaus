# Driving the command-line apps from a job

The hand-off between a character and an app is a file path. There is no shared bus: each command-line app reads and writes files. A job writes a steps file or a script, runs the `-cli`, reads what it prints, and hands a path to the next job. MCP mode is not used.

SolidCraft is an independent app (its package says so) that the owner uses alongside the ArtCraft suite; it is not made by ArtCraft.

## Rules

- Run only the `-cli` binaries: `figcraft-cli`, `vectorcraft-cli`, `pdfcraft-cli`, `solidcraft-cli` and `cadcraft-cli`.
- Never start `figcraft`, `vectorcraft`, `pdfcraft`, `solidcraft`, `cadcraft`, `filmcraft`, `effectcraft` or `lightcraft` (the names without `-cli`): they open a window and block the session.
- Never call `artcraft-launcher`, not even with `--help`. It updated the launcher from 0.6.1 to 0.14.1 when it was called once, and it installs apps.
- Wrap every call in `timeout 20` for checks, and in a longer bound for a real build.
- Write only to the project's output directory, `/tmp` or the scratch directory.
- Every `figcraft-cli` call takes both roots: `--automation-read-root <dir> --automation-write-root <dir>`.
- Add `--no-system-fonts` to every `figcraft-cli` call that renders, so a render matches on every machine.
- `vectorcraft-cli run` takes no root flags: it answers `unknown run option` and exits 1. Give every step an absolute output path under the output directory, and save the step command beside the file so the SVG can be made again.
- `pdfcraft-cli info`, `check`, `audit` and `render` take no root flag. `pdfcraft-cli run` takes `--root`, and its tool `doc_open` takes `path`: use the schemas that `pdfcraft-cli tools` prints.
- `solidcraft-cli`, `cadcraft-cli`, and the apps that follow them, have no root flag on `run`, `exec`, `render`, `set`, `convert` or `snapshot`. The root and path flags in their `--help` are on `mcp` only (`solidcraft-cli mcp --allow-path`, `effectcraft-cli mcp --automation-*-root`), and MCP is not used. Confinement is by four things: every output path is absolute and under the output directory; the settings and data directories are set inside it (`CADCRAFT_CONFIG_DIR`, filmcraft's `--data-dir`, and `XDG_DATA_HOME`, `XDG_CONFIG_HOME` and `XDG_CACHE_HOME`); the saved command sits beside each artifact; and a scan test reads the saved command and every `path`, `file` or `out` value inside a script's JSON, and fails any that is relative or outside the output directory. A `path` can hide in the script, where the command line does not show it.
- Never `effectcraft-cli script` or `--eval` (they run JavaScript), never `mcp`, `--connect` or `--bridge` (they drive a running window), never `solidcraft-cli fuzz` or `bench-*`, and never `lightcraft-cli denoise-serve` or `merge` (`merge` writes next to its input).
- Side files are expected and listed: `.<name>.ecproj.lock` beside an opened EffectCraft project, `catalog.*` and `view.json` in a LightCraft library, FilmCraft's `.fcproj` on `--save-as`. A job's output directory holds them, and the hand-over lists any source file it did not write into.
- One `cadcraft-cli run` writes one `--export`: a second is refused with exit 2. More formats come from `convert` (`cadcraft-cli convert x.dxf x.svg`).
- Each row of the commands table and each verified run carries an app version and the date.

## FigCraft facts from the trials

What the email trials ran against `figcraft-cli`, one fact each, with the version, the date and the trial folder (kept with the study notes) that is the evidence.

- `run` paths are absolute (an image `path`, a script, an output), and `run` takes read and write roots (`--automation-read-root`, `--automation-write-root`) that hold them (run, figcraft-cli 0.16.0, 2026-11-07, trial-email/sports-4).
- Every shape needs `"parent": <frame id>`, or the export is blank: the shape sits on the page, `render` shows it and `export` of the frame does not. A new document's first frame has id 2, and child coordinates are relative to the frame (run, figcraft-cli version not recorded, 2026-11-07, trial-email/sports).
- A script cannot refer to an earlier layer by name: `"parent": "$f"` after `"as": "f"` is rejected, because a parent must be a node id. A new document hands out ids 2, 3, 4 in creation order, so a builder predicts them and checks each against the result lines (run, figcraft-cli 0.16.0, 2026-11-07, trial-email/sports-4).
- `image.place` refuses SVG ("The image format could not be determined"). Make a PNG of the mark first, with `vectorcraft-cli convert x.svg x.png --scale 2` (run, figcraft-cli version not recorded, 2026-11-07, trial-email/sports).
- `export` overwrites a source file whose name matches a frame: it names each file for its frame and writes into the folder it is given. Keep frame names unlike the source names, or export into another folder (run, figcraft-cli 0.16.0, 2026-11-07, trial-email/sports-2).
- A mask is the lowest layer of its frame and masks the layers above it. With the shape above the image the script runs with no error and masks nothing (run, figcraft-cli 0.16.0, 2026-11-07, trial-email/sports-4).
- `effect.add` needs `type` twice: in the command's params and inside the `effect` object. Without the second the step is rejected (run, figcraft-cli 0.16.0, 2026-11-07, trial-email/sports-4).
- Multiply goes on the clipped frame, not on the image: set on the frame that holds the photograph it takes the photograph's white away against the ground behind it, set on the image layer it does nothing (run, figcraft-cli 0.16.0, 2026-11-07, trial-email/tech-2).
- The radial gradient fill is `fills: [{type: "radialGradient", stops: ["#hex", "#hex"]}]`, set with `node.set`. A last stop equal to the ground makes the edge vanish (run, figcraft-cli 0.16.0, 2026-11-07, trial-email/tech-2).
- One failed step rolls back the whole script: nothing is saved, so a typo costs a whole run (run, figcraft-cli 0.16.0, 2026-11-07, trial-email/sports-4).
- `export --scale 2` does not sharpen a small source: it is the same drawing at twice the pixels, so a 400 px photograph is enlarged and soft. `--scale 1` and `--scale 2` both exited 0, to 600 and 1200 px wide (run, figcraft-cli 0.16.0, 2026-11-07, trial-email/sports-4).

Not run: `command.batch` with `as` (it lists `as?` among its parameters, and whether it lets a step refer to an earlier layer is not known).

## Verified runs

Each wrote only under a scratch directory, with `timeout 20`, and no window was opened.

1. `figcraft-cli run steps.json --out hero.figcraft --no-system-fonts` and both roots, with two steps (`frame.create` 600 by 300 with `props.fill`, `text.create`), printed one JSON line per step and `wrote hero.figcraft`. `render hero.figcraft -o hero.png` wrote a 600 by 300 PNG. `export hero.figcraft -o hero.pdf --format pdf` wrote the PDF.
2. `vectorcraft-cli run --cmd file.new --params '{"width":256,"height":256,"units":"Pixels","backgroundContents":"white"}' --cmd shape.rectangle --params '{...,"radius":24}' --export mark.svg` printed one JSON result per step and wrote a valid SVG with a `viewBox`.
3. `pdfcraft-cli` on that PDF: `info` printed a JSON summary, `check ... --json out.json` printed `checked 1 files: {"ok": 1}`, `audit` printed no findings, `render --page 1 --dpi 72` wrote a PNG.
4. Headless Chrome on a one-table HTML file wrote a PNG at the window size, under `timeout 20`.
5. `figcraft-cli export hero.figcraft -o assets/ --format png --no-system-fonts` and both roots, run 2026-11-07 on the file of run 1, wrote `assets/hero.png`, a 600 by 300 PNG: one file per top-level frame, named for the frame.
6. `solidcraft-cli run massing.json --results --out massing.step --save massing.sc --json-out massing.run.json`, solidcraft-cli 0.30.1, 2026-11-07, with a `file.new`, four `solid.box` steps each named with `body_name`, and an `inspect.measure`: exit 0, four bodies created, and `massing.step` starts `ISO-10303-21;`.
7. `solidcraft-cli eval massing.sc --json-out massing.measure.json`, solidcraft-cli 0.30.1, 2026-11-07, on the model of run 6: exit 0, every body `closed: true`, the slab `volume_mm3` 28800000000.0 with bbox max `[12000.0, 8000.0, 300.0]`, and `total.volume_mm3` 58350000000, the sum of the four bodies. The two walls overlap by 200 by 200 by 3000 mm, so the total counts that overlap twice. The same script run into a fresh directory gave the same total. With `name` in place of `body_name` the bodies are `Body1` to `Body4`: `name` names the feature.
8. `solidcraft-cli snapshot massing.sc --out massing-iso.png --view iso --width 800 --height 500`, solidcraft-cli 0.30.1, 2026-11-07: exit 0, an 800 by 500 PNG, and read as an image it shows the slab, a wall and the roof plane.
9. A script with `file.export_view_dxf`, solidcraft-cli 0.30.1, 2026-11-07: with no `fov`, or with `"fov":60`, it exits 1 with `invalid parameters for file.export_view_dxf: invalid camera`. With `"pitch":1.5707963` and `"fov":0` it wrote `massing-plan.dxf`, 3,926 bytes. The `path` is inside the script, so a command-line scan does not see it.
10. `cadcraft-cli info massing-plan.dxf`, cadcraft-cli 0.18.0, 2026-11-07, on the DXF of run 9: exit 0, `"counts": {"Line": 4}`. It is the roof outline only, because a parallel top view hides what is below the roof.
11. `cadcraft-cli run --metric` with `units {"lunits":2,"luprec":0}`, three `layer.new` (`WALLS`, `DIMS`, `NOTES`), a `rectang`, a `dimstyle`, two `dimlinear` and two `text` commands, `--save plan.dxf --export plan.pdf`, cadcraft-cli 0.18.0, 2026-11-07: exit 0, one JSON line per command, and both files written. `cadcraft-cli info plan.dxf` counted `Dimension` 2, `Polyline` 1 and `Text` 2, and listed the three layers.
12. Two `--export` in one `cadcraft-cli run`, cadcraft-cli 0.18.0, 2026-11-07: exit 2, `the argument '--export <OUT.png>' cannot be used multiple times`. `cadcraft-cli convert plan.dxf plan.svg` and `convert plan.dxf plan.png` both exit 0. The PNG is 2400 by 1600. The SVG has a `viewBox` and no `<text>` element, because the text is drawn as strokes.
13. `pdfcraft-cli check plan.pdf`, pdfcraft-cli 0.11.0, 2026-11-07, on the PDF of run 11: `checked 1 files: {"ok": 1}`, exit 0. `info` reports the creator `CADCraft` and a first page of 841.89 by 595.28 pt, an A4 landscape sheet.
14. Dimension text on the PNG of a 12,000 mm plan, cadcraft-cli 0.18.0, 2026-11-07, read as an image: with the default dimstyle the dimension is drawn as a few dots, with no text and no arrows. With `dimstyle {"name":"Standard","current":true,"DIMSCALE":1,"DIMTXT":350,"DIMASZ":250,"DIMEXE":150,"DIMEXO":100,"DIMDEC":0}` the text reads `12000` and `8000`, and the arrows are drawn. Legibility is looked at on the render and is not something a command guarantees.
15. `filmcraft-cli --data-dir D --save-as shots.fcproj run shots-base.jsonl`, filmcraft-cli 0.18.0, 2026-11-07, with `file.newSequence` (1920 by 1080 at 24) and `file.newColorMatte` of 21 seconds: exit 0, one `"ok":true` line each, and the matte's item id is on the second line (8 in a new project, and the skill reads it from the line). Then `--project shots.fcproj --save run shots.jsonl` with `timeline.place`, six `markers.add` with `seconds`, `name` and `comment`, `file.exportEdl` and `file.exportOtio`: exit 0, every line `"ok":true`. The EDL holds six `* LOC:` lines named `S01 ELS` to `S06 ECU`, in order, and the OTIO file is written (about 106 KB, its markers not read). A line that fails fails the run and nothing is saved.
16. `filmcraft-cli --project shots.fcproj inspect sequence`, filmcraft-cli 0.18.0, 2026-11-07, on the project of run 15: each marker's `name` is `S<nn> <size>`, its `comment` is the angle and the movement joined by `; `, and its `start` is the sum of the lengths before it in ticks (254016000000 to the second): starts 0, 4, 9, 12, 16 and 19 seconds. The same list on a sequence with no clip under the markers exports an EDL with no `* LOC:` line (35 bytes), which is why the markers sit on a placeholder matte.
17. `filmcraft-cli --project shots.fcproj render --seconds S --out f.png`, filmcraft-cli 0.18.0, 2026-11-07, at each marker's start: exit 0 and a 1920 by 1080 PNG each. A render that exits 0 has no offline media; `--allow-offline` is never passed.
18. `figcraft-cli run storyboard.json --out storyboard.figcraft --no-system-fonts` and both roots, figcraft-cli 0.16.0, 2026-11-07, with six `frame.create` steps (960 by 540, `props.fill`, named `S01` to `S06`) each followed by `text.create` steps with `parent` the frame's id: every line `ok`, and the frame ids are the ones predicted (2, 7, 11, 15, 19 and 24 in the sample: a frame, then its texts, in creation order). `export storyboard.figcraft -o frames/ --format png --no-system-fonts` and both roots wrote `S01.png` to `S06.png`, each 960 by 540, and read as an image the text is in the frame. A text step with no `parent` is the blank-export fault of the FigCraft facts below.
19. `filmcraft-cli --data-dir D --save-as storyboard.fcproj import S01.png … S06.png`, filmcraft-cli 0.18.0, 2026-11-07: exit 0, `"errors": []` and six item ids in order (1 to 6 in a new project; the skill reads them from the output). Then `--project storyboard.fcproj --save-as animatic.fcproj run animatic.jsonl` with `file.newSequence` (960 by 540 at 24), six `timeline.place` each with one `item`, `seconds` and `duration` of `{"seconds":N}`, and `file.exportMedia` as a GIF at scale 0.5: exit 0, `offlineMedia` empty, 504 frames, and a 480 by 270 GIF. `inspect sequence --compact` reads back the clips on `video[0].items` with `durationFrames` 96, 120, 72, 96, 72 and 48, which are the table's seconds times 24.
20. The same `timeline.place` with `items` in place of `item` and a `duration`, filmcraft-cli 0.18.0, 2026-11-07: exit 1, and the error is to give `item` or `items`, and no `sourceIn` or `duration` with `items`. Placed with `items` and no duration, a still is held for 120 frames (five seconds at 24), so the skill places one still at a time.
21. `effectcraft-cli --empty --json --save-as motion.ecproj run --commands motion.json`, effectcraft-cli 0.22.0, 2026-11-07, with `comp.new` (960 by 540, 2 seconds, 24 fps, background `#0b2a44`) and `layer.newText`: exit 0, `{"comp":1}` and `{"layer":2}`. Two `--project motion.ecproj --save set Title title transform/opacity V --time T` (0 at 0, 100 at 1) exit 0, and `get … --time 0.5` returns two keys, `compTime` 0.0 and 1.0, both `"in":"Linear"`, and the value 50.0 at the midpoint.
22. A `set` with no `--save`, effectcraft-cli 0.22.0, 2026-11-07, on a copy of the project of run 21 (`set … transform/opacity 42 --time 0`): exit 0, and `get … --time 0` still returns 0.0 and one key, so the key was lost when the process ended. Every `set` carries `--save`.
23. `effectcraft-cli --project motion.ecproj render-frame --comp Title --time 1.5 --out poster.png`, effectcraft-cli 0.22.0, 2026-11-07: `rendered 960x540 at 1.500s`, a 960 by 540 PNG that reads as the title in white on the dark ground. `render --comp Title --out motion.gif --format gif --resolution half`: a 480 by 270 GIF of 48 frames. A `.motion.ecproj.lock` file of 0 bytes appears beside any project opened with `--project`, and the hand-over lists it.

`test/artcraft.test.mjs` repeats runs 1 to 3, 5 to 13 and 15 to 23 against a temporary directory, each test needing only the apps it calls. Run 14 is read by eye. Runs 1 to 5 were made on older versions; `npm run test:artcraft` repeated runs 1 to 3 and 5 on 2026-11-07 on figcraft-cli 0.16.0, vectorcraft-cli 0.22.0 and pdfcraft-cli 0.11.0, and passed. `npm run test:artcraft` fails when a command-line app a test needs is missing, and `npm test` skips that test with the reason printed.

## Not run, so not relied on

`figcraft-cli render` with `--scale`; `solidcraft-cli render` (a path-traced render that has not been run or timed), `fuzz` and `bench-*`; any `mcp`; CADCraft `hatch`, layouts and `mview`; whether a hosted runner can install any of these apps. FilmCraft 0.18.0 and EffectCraft 0.22.0 are installed and answer `--version`, and each has a row above. Not run: any export to a video format (`.mp4`, `.mov`) from either, `filmcraft-cli mcp` and `--bridge`, `bench-decode`, `effectcraft-cli mcp`, `bench` and `script`, whether the OTIO file carries the markers, and `--allow-offline`. LightCraft 0.19.0 has the row above and no job behind it.
